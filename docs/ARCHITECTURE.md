# 技术选型与架构

## 为什么使用 Rust 原生 GUI

| 方案 | 判断 |
| --- | --- |
| Electron | 开发方便，但引入 Chromium 与 Node，偏离小型桌宠的资源目标 |
| Tauri | 比 Electron 精简，但依赖平台 WebView，透明窗口、鼠标穿透和平台行为仍需原生层 |
| Python + Qt | 迭代快，但要携带 Python 与 Qt 运行时 |
| Rust + egui/eframe + Glow | 事件驱动重绘、原生透明窗口；继续用于宠物 |
| Tauri 2 + Vue 3 独立面板 | 使用系统 WebView 绘制精细界面；按需启动、关闭后退出进程 |

没有宣称“Rust 必然低内存”。实际资源取决于驱动、窗口数量、字体纹理和重绘频率。项目以发布构建测量为准。

## 线程与窗口

- 宠物主线程：平台事件循环、透明宠物窗口、托盘与热键。
- 按需面板进程：Tauri 窗口与 WebView，独立事件循环，通过父子进程 stdin/stdout 管道通信；关闭窗口即退出，父进程失联也退出。
- 一个轻量悬停探测线程：每 75ms 只读取光标坐标，仅在角色命中状态变化时唤醒 UI，避免 1–2 FPS 动画导致点击穿透切换迟钝；不读取键盘或保存鼠标轨迹。
- 一个桌面操作线程：执行有超时的系统操作，不让 Finder 重启阻塞 UI；平时阻塞等待消息。
- 一个内容服务线程：持有 SQLite 连接，处理文件复制、哈希、预览、下载和导出；空闲时等待消息，每分钟清理过期数据。
- Windows 的独立消息窗口接收剪切板变化通知，最多有限重试；虚拟附件通过独立 STA 线程接收。macOS 的主线程计时器每 250ms 检查变化计数，文件承诺使用原生操作队列。
- 一个按需守护进程：仅图标隐藏期间运行，每 250ms 检查父进程和租约期限。
- 控制面板只在打开时创建。宠物没有高频游戏循环；事件到达或下一个动画期限才请求重绘。

面板六页迁移至 `panel/src/App.vue`，后端行为、配置和 SQLite 仍由宠物进程独占。面板只在存在时轮询快照；正文搜索、缩略图、复制与导出交给内容服务工作线程。昵称使用 Vue 编辑缓冲区与浏览器原生输入法，保存时由 Rust 统一截断和校验。双方内嵌同一完整中文字体。皮肤预览从已校验的定义生成静态 SVG 或 PNG 数据，不在面板内启动第二份宠物动画循环。

生产入口默认打开 Tauri；`--legacy-panel` 仅保留用于开发对照，不作为自动回退。主程序不依赖 Tauri，面板可执行文件缺失时提示构建或恢复安装。生命周期、协议与测试见 [TAURI_PANEL.md](TAURI_PANEL.md)。

## 行为模型

`Engine` 不依赖 GUI / OS，以单调时间和种子接收交互，输出状态和 `HideIcons` / `RestoreIcons` 效果。冷落阈值为 N / 2N / 3N，一轮最多升级一次。互动重置升级；忙碌模式暂停 30 分钟；安静或撤销授权立即结束正在发生的高级效果。

动画用简单矢量图形而非视频或大量纹理。主窗口按同一套动画姿态计算身体、耳朵、手脚和尾巴的命中区域；透明空隙不算角色命中。悬停边界变化时切换鼠标穿透；追逐期间全窗口穿透。点击或拖拽宠物属于用户主动交互，可获得焦点；自动捣蛋不请求焦点。

## 皮肤定义与绘制

`src/skin/` 将 UI 数据模型、资源包读写和通用渲染分开。`skins/default` 的 JSON 是默认角色的唯一造型定义，同一文件内嵌为安全回退；换色和 PNG 示例使用同一模型。行为引擎输出的十种情绪绑定到皮肤状态，皮肤只定义外观，不取得桌面操作权限。

桌面窗口和悬停探测共享 `Arc<Skin>`；Tauri 面板通过管道获取这份定义生成的静态预览。状态、动画位移、形状和 PNG 当前帧的透明度同时用于绘制与命中。画布、追逐锚点、气泡和恢复按钮布局来自皮肤定义；外部图片仅在加载时解码和创建纹理。控制面板布局不由皮肤替换。

`.mochi` 用 12 字节版本头封装 ZIP，运行时直接读取内存中的包，不自动解压。普通 ZIP 和目录也走相同的校验流程；独立打包、解包和校验命令不启动 GUI。格式细节及资源上限见 [皮肤说明](SKINS.md)。

## 恢复协议

1. 获取桌面操作锁，拒绝覆盖未结束的恢复租约。
2. 读取并保存原始状态。如果原先已隐藏，拒绝参与此次捣蛋。
3. 原子写入带唯一身份、平台、父 PID、到期时间的恢复日志。
4. 启动独立守护进程；如果启动失败，不修改桌面。
5. 执行隐藏，失败时立即回滚。
6. 定时、用户恢复、退出或守护检测到父进程失联时恢复。
7. 仅恢复成功后删除日志。失败保留日志，便于下次启动和手动恢复。

守护使用唯一租约身份，旧守护不会处理新的租约。墙钟到期与守护的单调时间上限共同防止调时导致无限隐藏。桌面锁防止 UI 和守护并发修改设置。macOS 恢复时保留设置原本是否存在，且不覆盖用户后来已经改回显示的状态。

## 存储与隐私

通过 `directories` 使用平台本地应用数据目录：配置 JSON、单实例锁、桌面锁和短期恢复日志；新增 `content/` 内容库。没有遥测或上传，仅在主动收纳远程资源且下载开关开启时发出 HTTP/HTTPS 下载请求。损坏设置先备份，再使用安全默认值；未知恢复日志版本不会被忽略或删除。

## 剪切板与原生拖放

`src/content/` 提供共享数据模型与串行工作队列，SQLite WAL 保存来源、时间、收藏、状态、错误和全文搜索数据。正文、图片、独立文件／目录副本按 SHA-256 保存，数据库引用控制共享资源释放；文件先写临时目录再发布。启动恢复中断记录并清理残留，空间限额只淘汰非收藏剪切板记录。界面只接收元数据、预览和进度，不在绘制函数中复制文件。

`src/native_content/` 按窗口生命周期绑定本进程的宠物及设置窗口，保留原有窗口事件处理。Windows 使用 `AddClipboardFormatListener` 和 OLE `IDropTarget` / `IDataObject` / `IDropSource`，关闭 winit 原文件拖放，避免重复接收。附件的文件描述符和流在当次拖放期间落地，支持源端的异步 OLE 能力，并通过 COM 封送转入 STA。macOS 转发原窗口 delegate，使用 `NSPasteboard`、原生 dragging session 和 `NSFilePromiseReceiver`。

原生桥在暂停／恢复时重置变化基线，忽略自身写入，尊重敏感内容格式；权限拒绝停止反复读取。接收时暂停宠物运动和拎起，鼠标穿透根据本窗口接收区域协调，无全局鼠标钩子。拖出只允许 COPY，先准备真实导出路径，文本和图片另提供原生表示；系统剪切板或拖放仍引用的文件暂不清理。来源浏览器仅提供链接时不推测下载，不读取其登录凭据。详细策略见 [CONTENT.md](CONTENT.md)。
